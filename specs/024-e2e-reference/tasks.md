- `.ycsf/resources.yaml` отсутствует в каноническом дереве (plan §Project Structure). Legacy compose-путь (B-dialect) строит resource-index из `.ycsf/resources.yaml` (`packages/composer/src/resource/resource-index.ts:175`: ENOENT → пустой индекс → `${resources...}`-ссылка на необъявленный ресурс = `RESOURCE_REF_NOT_DECLARED`) — НО **builder-путь (026) не валидирует refs по resources.yaml**: `collectResourceReferences` собирает `${resources.<type>.<name>.<property>}` из финального артефакта (`packages/composer/src/builder/artifact.ts:45`, `builder/index.ts:102`), materializer-зер `replaceResourceRefs` мапит `domain.name` → `yandex_*` по D-4-таблице (`materializers-core/yandex-api-gateway/ref-resolver.ts`) из identity C-модели. => logical-ссылки направлены на **apps** (app_id), resources.yaml не нужен.
- pilot-model отклоняет объявление `functions.<app_id>` в resources.yaml при совпадении с `app_id` из apps.yaml (`packages/pilot/src/model/resources.ts:71-91`, `PML_IDENTITY_COLLISION`); `containers.*`/`buckets.*` НЕ проверяются этой коллизией.
- `ycsf build` последователен по `orderedAppIds` и fail-fast по приложению (`packages/pilot/src/build/index.ts:208-290`): builder-throw → `CLI_BUILD_FAILED` и остановка всего build; cache-hit (`restoreBlob`) **НЕ вызывает** builder (docker не требуется на тёплом кэше).
- `ycsf check --validate-tf` существует (`packages/pilot/src/cli/check.ts:24,52`).
- Docker daemon в этом окружении **отсутствует**: cold-сборка analytics без daemon → документированный fail-fast на стадии `build` (builder-уровень `BLC_*` / connect-to-daemon, наружный слой `CLI_BUILD_FAILED`); hermetic-путь 027 (fake-docker, `docker image inspect --format '{{.Id}}'`) воспроизводит локальный digest БЕЗ daemon.
- `terraform plan` без кред → детерминированный стоп на provider-границе (`one of 'token' or 'service_account_key_file'`), НОЛЬ сетевых обращений к Yandex Cloud; единственная сеть — registry.terraform.io при `terraform init` (plan.md:236-240).

## Документированные границы (НЕ блокируют pipeline; фиксируются словами в README/тестах)

1. **Docker-стадия analytics**: полный 4-приложенческий путь требует локального Docker daemon (Linux CI его даёт); без daemon холодный `ycsf build` останавливается ровно на стадии `build` с понятной stage-диагностикой (FR-013; «не тихий» пропуск, A-4). Корректность docker-builder доказана hermetic-тестами 027; эталон воспроизводит локальный digest через fake-docker для golden-захвата.
2. **Terraform plan без креденшалов**: заканчивается ровно на provider-границе с actionable text (FR-019, D-5); всё ДО plan (check/build/materialize/init/validate) проходит всегда, без облака (SC-004). Реальный plan (с креденшалом контрибьютора) вне CI.
3. **linux-requirements**: полный путь (docker-стадия + plan с креденшалом) — только на Linux CI; macOS/darwin локально доказывается free-path (без daemon: check, build пользовательских apps, materialize, init/validate/plan-граница) + hermetic golden. Windows не поддерживается (POSIX-скрипты `&&`).
